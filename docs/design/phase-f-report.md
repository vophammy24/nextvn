# NextVN Phase F — responsive and accessibility review

Date: 2026-10-15 (Asia/Saigon). Branch: `develop`.

## Scope and outcome

**PASS with limits:** all 20 implemented routes were exercised in isolated Microsoft Edge at 1920, 1366, 1024, 768, 390, and 360 CSS pixels. The final [machine-readable matrix](phase-f/final/results.json) contains 120 route/width checks, 42 screenshots, and interaction measurements. No uncaught page errors, unmapped fixture requests, document-level horizontal overflow, or unlabeled form controls were found. This is a browser and source review against relevant [WCAG 2.2 AA criteria](https://www.w3.org/TR/WCAG22/), not a certification or a screen-reader audit.

## Accessibility findings and fixes

- **PASS in sampled states:** visible keyboard focus, native button semantics, labeled controls, named scroll regions, ARIA pressed/expanded states, dialog containment and restoration, and reduced-motion CSS were verified by browser checks or source review. Reduced-motion emulation reduced sampled animation and transition durations to 0.01ms.
- **Fixed:** Staff and Owner loading panels now announce through `role="status"`; Staff query errors and table/shift mutation failures announce through `role="alert"`. Decorative spinner/error icons were hidden from assistive technology where touched. Tables and Shift failure messages replaced blocking browser alerts with inline feedback; request payloads and transitions are unchanged.
- **Fixed:** four low-contrast Owner labels in Revenue and Subscription used legacy muted greens. They now use the shared secondary text token. The final 360px automated contrast sample reported zero flags. Its solid-background approximation does not assess gradients, images, focus-indicator contrast, every state, or every viewport; manual assistive-technology review remains pending. [WCAG text contrast reference](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum).
- **Remaining:** Owner branch edit still uses a browser prompt; replacing it with a full accessible form would affect an existing edit workflow and was not attempted in this phase. No full screen-reader run, 200%/400% browser zoom, or cross-browser mobile test was performed.

## Visual consistency and changed files

The final captures retain the NextVN logo, navy shell, blue primary actions, restrained yellow accent, shared Inter/system stack, semantic status colors, and distinct role-navigation icons. Staff, Manager, Owner, and public screens use the Phase B token system. Some original Owner CSS retains unused green-era rules under token overrides; removing that legacy stylesheet wholesale is outside this safe regression pass.

Phase F changed `client/src/pages/staff/POSPage.tsx`, `TablesPage.tsx`, `OrderHistoryPage.tsx`, `ShiftSummaryPage.tsx`, `client/src/pages/owner/OwnerWorkspace.tsx` and `OwnerWorkspace.css`, plus `client/src/tests/tables-workflow.test.tsx`, `shift-confirmation.test.tsx`, and the isolated `docs/design/audit-browser.cjs` harness. The 120-case matrix passed after the layout and contrast fixes; focused mocked table and shift tests passed (3 tests across 2 files) after the failure-feedback changes. No significant regression was detected, so Phase G proceeded.
